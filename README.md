# week. — планировщик Вадима и Сони

Готовый стартовый каркас: frontend + Supabase Auth + PostgreSQL + RLS + предложения общих задач.

## Быстрый запуск без базы

Открой `index.html` через локальный сервер. Если `config.js` пустой, сайт покажет кнопку «Демо-режим».
Демо-данные сохраняются в localStorage.

Для нормальной облачной версии используй Supabase.

## Подключение Supabase

1. Создай проект в Supabase.
2. Открой SQL Editor.
3. Выполни весь `supabase.sql`.
4. В Supabase возьми Project URL и публичный anon/publishable key.
5. Вставь их в `config.js`:
   `window.SUPABASE_URL = "...";`
   `window.SUPABASE_ANON_KEY = "...";`
6. Запусти сайт через локальный HTTP-сервер или разверни его на Cloudflare Pages.

Никогда не вставляй в `config.js` service_role key.

## Важное про общие задачи

При выборе «Предложить другому» создаётся `task_requests`.
Получатель видит предложение и может:
- принять;
- отклонить;
- предложить другое время.

После принятия создаётся общая задача.

## Cloudflare Pages

Загрузить этот проект в GitHub и подключить репозиторий к Cloudflare Pages.
Build command для обычного статического сайта не нужен.
Build output directory: `/` (или корень репозитория).

## Что ещё стоит сделать перед публичным запуском

- заменить двухпользовательскую RLS-логику на отдельную таблицу memberships;
- добавить полноценный realtime listener в `app.js`;
- добавить браузерные уведомления;
- добавить таймер и полноценные time_logs;
- добавить drag-and-drop;
- добавить более строгую валидацию;
- проверить RLS в двух аккаунтах;
- подключить собственный домен только после тестирования `*.pages.dev`.

## После подключения Supabase

1. Заполните `config.js` значениями Project URL и Publishable/anon key.
2. Зарегистрируйте два реальных аккаунта через форму приложения.
3. Войдите первым аккаунтом и создайте задачу с назначением «Предложить другому».
4. Войдите вторым аккаунтом: предложение появится в разделе «Предложения».
5. Нажмите «Принять» — создастся общая задача, видимая обоим пользователям.

В текущей версии выбор второго пользователя выполняется через таблицу `profiles`, поэтому demo-ID больше не используются для Supabase-режима. Realtime для задач и входящих предложений также включён в клиенте.
