# week. — планируй своё время и дела вместе с друзьями

**week.** — веб-планировщик для личных и совместных задач. Он помогает распределять дела по дням, учитывать постоянное расписание, следить за выполнением и договариваться о совместных планах. Приложение не ограничено двумя аккаунтами: в текущем небольшом развёртывании им смогут пользоваться до 10 человек.

## Начало работы

1. Откройте опубликованный сайт week. (адрес зависит от того, где развёрнут проект).
2. Выберите **«Регистрация»**, укажите имя, email и пароль. Если аккаунт уже есть, нажмите **«Войти»**.
3. При первом входе заполните школьное расписание и дополнительные занятия, если они у вас есть. Этот шаг можно отложить.
4. Откройте раздел **«Сегодня»** и нажмите **«+ Добавить задачу»**.

Для знакомства с интерфейсом предусмотрен **демо-режим**. Демо-данные хранятся локально в браузере; это не общий аккаунт и не замена регистрации для совместной работы.

## Возможности

### Задачи и календарь

Создавайте задачи с названием, описанием, датой, временем, длительностью, дедлайном, категорией и приоритетом. Можно отметить фиксированное время и настроить повторение каждый день, каждую неделю или по будням. В календаре переключайтесь между режимами **«День» и «Неделя»**; регулярные занятия учитываются в расписании. При создании задачи week. предупреждает о пересечениях по времени с другими задачами и занятиями; при необходимости пересечение можно разрешить вручную.

### Чек-листы и незавершённые дела

В редакторе задачи можно добавить до 50 пунктов чек-листа. Чтобы отмечать их выполненными прямо из календаря, нажмите кнопку **☑** с числом готовых пунктов у задачи. Чек-листы хранятся в JSON-поле самой задачи, без дополнительных таблиц. Для повторяющейся задачи чек-лист общий для всей серии.

Кнопка **«↪ Перенести»** появляется, когда у вас есть незавершённые задачи с прошедшей датой. Выберите нужные и перенесите на сегодня. Во избежание конфликтов ранее заданное время переносимых задач очищается. Повторяющиеся задачи не переносятся, общие задачи другого владельца — тоже.

### Расписание

При первой настройке можно указать уроки и дополнительные занятия. Если расписание изменилось, откройте **«Настройки» → «Изменить расписание»**. Если вы не учитесь в школе или у вас нет дополнительных занятий, соответствующие шаги можно пропустить.

### Друзья и совместные дела

В **«Настройках»** задайте свой username, чтобы другие пользователи могли вас найти. В разделе **«Друзья»** найдите человека по username и отправьте заявку. Там же отображаются друзья, входящие и отправленные заявки.

При создании задачи выберите один из вариантов:

- **«Только мне»** — личная задача.
- **«Общая с другом»** — задача для совместного планирования.
- **«Предложить другу»** — предложение, на которое получатель может ответить в разделе **«Предложения»**: принять, отклонить или предложить другое время.

Чтобы выбрать друга при создании задачи, сначала добавьте его в друзья. Совместная работа предназначена для зарегистрированных пользователей, а не для локального демо-режима.

### Шаблоны, таймер и статистика

В разделе **«Шаблоны»** сохраняйте параметры частых задач, чтобы не заполнять их заново. Таймер помогает учитывать время, потраченное на задачу. В **«Статистике»** доступны нагрузка по дням и распределение по категориям.

### Настройки и данные

Можно изменить имя, username, тему оформления (системная, светлая или тёмная), стандартную длительность задачи и параметры напоминаний. Для браузерных уведомлений необходимо разрешение браузера; фактическая доставка зависит от настроенного развёртывания и поддержки браузера. В разделе **«Данные»** есть экспорт и импорт JSON.

## Для разработчиков: самостоятельный запуск

Проект представляет собой статический frontend (`index.html`, `style.css`, `app.js`) с Supabase для регистрации и хранения данных. Для обычного пользователя настройка Supabase не требуется: она нужна только владельцу развёртывания.

1. Создайте проект в Supabase и выполните `supabase.sql` в **SQL Editor**. Если база уже существует, вместо повторного выполнения полной схемы выполните **`MIGRATION_1_1.sql`**. Это добавит два поля `checklist` в таблицы `tasks` и `task_requests` без удаления ваших данных.
2. Скопируйте `config.example.js` в `config.js` и укажите Project URL и публичный anon/publishable key. Проверьте формат переменных в примере конфигурации.
3. Запустите файлы через локальный HTTP-сервер или опубликуйте статический сайт, например на Cloudflare Pages. Для обычного статического развёртывания команда сборки не нужна; выходной каталог — каталог с `index.html`.
4. Проверьте регистрацию, создание задач, добавление друзей и предложения задач на нескольких отдельных аккаунтах.
5. Для push-напоминаний используйте отдельную инструкцию [`PUSH_SETUP.md`](PUSH_SETUP.md). В проекте также есть Service Worker (`sw.js`) и Supabase Edge Function `send-task-reminders`.

**Безопасность:** никогда не помещайте `service_role` key или другие секреты в клиентский `config.js` и публичный репозиторий. При изменении SQL-схемы проверяйте политики доступа (RLS) для личных и общих данных разных пользователей. Не публикуйте локальные служебные файлы и зависимости из `node_modules` без необходимости.

## Структура проекта

| Файл или каталог | Назначение |
| --- | --- |
| `index.html` | Разметка приложения |
| `style.css` | Оформление и адаптивный интерфейс |
| `app.js` | Логика задач, расписания, друзей и других разделов |

| `supabase/functions/send-task-reminders/` | Серверная функция напоминаний |

## Иконка сайта и приложения

В качестве иконки используется исходная картинка `week.png` (она сохранена без изменений). Из неё подготовлены `favicon.ico`, `week-32.png` для вкладки браузера, `week-180.png` для iOS и `week-192.png` / `week-512.png` для установки PWA. Ссылки на иконки указаны в `index.html`, а размеры для PWA — в `manifest.webmanifest`.

Если после публикации на GitHub Pages осталась старая иконка, дождитесь завершения публикации и откройте сайт с принудительным обновлением (Ctrl+Shift+R). Установка PWA или ярлыка, созданная до обновления, иногда сохраняет старую иконку — удалите только установленный ярлык или приложение и добавьте его заново. Базу Supabase для изменения иконки обновлять не нужно.
