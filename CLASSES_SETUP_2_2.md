# week. 2.2. Классы и администратор

## Порядок обновления рабочей базы

1. Сохрани резервную копию Supabase. Не запускай `supabase.sql` поверх работающей базы.
2. Проверь, что применены `MIGRATION_1_1.sql`, `MIGRATION_1_6.sql`, `MIGRATION_2_0.sql` и `MIGRATION_2_1.sql`.
3. Выполни `MIGRATION_2_2_CLASSES.sql` в Supabase SQL Editor. Миграция создаёт только новые таблицы и функции. Старые задачи и расписание не удаляются.
4. Открой `ADMIN_SETUP_2_2.sql`, скопируй запрос в SQL Editor и замени `ТВОЙ_EMAIL_ЗДЕСЬ` на email **своего уже зарегистрированного аккаунта**. Нажми Run. Если аккаунт не найден, запрос вернёт ошибку и не выдаст права кому-то другому.
5. Замени файлы сайта из ZIP на GitHub и дождись публикации. Если браузер показывает прежнюю версию, выполни обновление страницы с очисткой кеша или переустанови ярлык PWA.
6. Войди своим аккаунтом и открой «Группы». Появится управление классами. Создай, например, 10А, и скопируй код.
7. Проверь регистрацию нового тестового пользователя с кодом класса. После входа должны появиться класс, его участники и школьное расписание.

**Важное замечание:** я не могу выдать роль непосредственно в твоём рабочем Supabase без информации об аккаунте и доступа к проекту. Она выдаётся SQL-командой на шаге 4. Демо-режим условно считает Вадима администратором только для локальной проверки интерфейса.

## Что может администратор

- Создавать несколько классов, например 9А, 9Б и 10А.
- Получать код каждого нового класса и менять его, если старый больше не нужен.
- Выбирать класс из списка и менять школьное расписание этого класса.
- Видеть список участников класса и отправлять им обычные заявки в друзья.

Роль проверяется в PostgreSQL через `week_admins` и защищённые функции. Нельзя назначить себя администратором через настройку в браузере.

## Как вступает ученик

На экране регистрации есть поле «Код класса». Оно необязательное, так что пользователи без кода по-прежнему могут пользоваться week. Если код указан правильно, в базу добавляется участие в классе вместе с созданием аккаунта. Это работает даже при включённом подтверждении email. Для уже существующего аккаунта во вкладке «Группы» предусмотрено отдельное поле кода. Один пользователь может состоять в одном классе. Возможность самостоятельно менять класс пока не реализована.

Код состоит из 24 шестнадцатеричных символов и предназначен для нескольких участников. В базе хранится SHA-256-хеш кода. Повторно показать прежний код после закрытия нельзя, администратор должен создать новый. Поэтому передай код участникам сразу или сохрани отдельно.

## Расписание и приватность

Все ученики одного класса видят одинаковые школьные уроки. Они хранятся по одному разу в `class_schedule_items`, а не дублируются в `schedule_items` каждого ученика. Дополнительные личные занятия остаются в `schedule_items` и не показываются другим членам класса. Если у пользователя уже были персональные школьные уроки, после вступления в класс они скрываются в календаре, но не удаляются из базы.

Участникам открыты только имя и username одноклассников, не их email, личные задачи и дополнительные занятия. Кнопка «+ В друзья» отправляет обычную заявку, дружба не создаётся автоматически. Администратор не получает права читать чужие личные задачи только из-за своей роли.

## Хранение и актуализация

Приблизительно 30 уроков одного класса занимают только 30 записей в таблице расписания, независимо от количества учеников. Для 50 активных пользователей это намного экономнее дублирования одинаковых уроков. Если администратор изменит расписание, ученики увидят изменения при следующем обновлении данных, возвращении к активной вкладке или очередной фоновой проверке (примерно раз в три минуты).

Ни одно ограничение на регистрацию ровно 50 человек не вводится. 50 активных пользователей являются ориентиром, а не обещанием производительности без тестов на реальном Supabase.
