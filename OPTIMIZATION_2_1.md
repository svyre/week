# week. 2.1. Оптимизация для группы до 50 человек

Версия подготовлена на основе полного архива week. 2.0.1. Пользовательские данные и настройки Supabase в `config.js` сохранены.

## Что изменено

| Файл | Изменение |
| --- | --- |
| `app.js` | Проверка предложений раз в 180 секунд вместо полной загрузки 11 наборов каждую минуту. Фоновая вкладка не опрашивает базу. Дублирующиеся полные запросы объединяются. |
| `app.js` | Базовый диапазон задач: 45 дней назад, 75 дней вперёд. Старые повторы и открытые дела тоже загружаются. При переходе в другую дату диапазон обновляется. |
| `app.js`, `MIGRATION_2_1.sql` | Поиск через `public_profiles` с публичными полями `id`, `display_name`, `username`; email доступен владельцу в `profiles`. |
| `send-task-reminders/index.ts` | Задачи одного календарного дня читаются один раз на запуск функции для подписчиков в этом часовом поясе. Отправка ограничена владельцем или участником общей задачи. Логи отправки событий проверяются пакетно. |
| `sw.js` | Кешируются только статические GET-ресурсы сайта; внешние API-ответы в кеш не попадают. |
| `MIGRATION_2_1.sql` | Индексы под периодические и адресные запросы; исправлено оповещение о выполнении общей задачи. |
| `MAINTENANCE_2_1.sql` | Проверка размера базы и примерные количества устаревших технических записей. Запросы не удаляют данные. |

## Установка на уже работающую базу

1. Сделай резервную копию базы Supabase.
2. Убедись, что раньше выполнены миграции 1.1, 1.6 и 2.0. Для push нужен `push_setup.sql`.
3. Выполни `MIGRATION_2_1.sql` в SQL Editor. Важно: выполнить **до** замены `app.js`, иначе поиск друзей не найдёт `public_profiles`.
4. Опубликуй содержимое `week-main` в GitHub Pages или другом статическом хостинге. Сохрани свои публичные настройки `config.js`.
5. Если настроен push: повторно разверни `supabase/functions/send-task-reminders/index.ts`. Проверка push на реальных подписках отдельно обязательна.
6. Проверь вход, создание задачи, поиск друга, предложение задачи, уведомления и переключение на старую/будущую неделю.

## О хранении и статистике

Ни одна пользовательская задача, чек-лист или история streak не удаляется автоматически. Старые завершённые задачи доступны при переходе к их дате. Не следует напрямую удалять выполненные задачи за 30 или 90 дней, пока не отделена полная историческая статистика: `time_logs` удаляются каскадно с задачами.

При длительном использовании задача без срока удаления может занимать базу годами. Проверяй реальный размер через `MAINTENANCE_2_1.sql`. Запросы используют приблизительную статистику строк, а не точные замеры производительности. Рекомендуется проверить реальную работу на 10–20 аккаунтах перед приглашением 50 человек.

## Что не обещает это обновление

Оно не ограничивает количество регистраций ровно 50, не меняет тариф Supabase и не заменяет нагрузочного тестирования. Пока нет замеров общего трафика, нагрузки PostgreSQL и работы сервера push, нельзя обещать поддержку любого количества одновременных пользователей.
